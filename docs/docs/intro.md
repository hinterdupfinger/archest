# Introduction

**Archest** is a modern, high-performance architecture testing framework built to safeguard the structural integrity of your codebase. It is heavily inspired by Java's [ArchUnit](https://www.archunit.org/) and Kotlin's [Konsist](https://docs.konsist.lemonappdev.com/), but features a unified, native Rust engine (`archest-core`) that parses Abstract Syntax Trees (ASTs) and executes rules across multiple ecosystems.

Archest currently provides official integrations for:
*   **Vitest & Jest** (JavaScript/TypeScript)
*   **JUnit 6** (Java/Kotlin)
*   **Kotest** (Kotlin DSL)

By codifying your architectural boundaries directly into your test suites, you can ensure they are automatically enforced on every local run and CI pipeline execution.

---

## Why Architecture Testing?

A common question is: *"Why do I need architecture tests if I already use linting tools (like Biome, ESLint, or Oxc)?"*

While modern linters are incredible for catching micro-level syntax errors, style issues, and simple code smells, they are fundamentally designed for **single-file analysis**. To maintain their speed, they analyze each file in isolation. They do not resolve cross-file dependencies, construct project-wide import graphs, or understand your domain architecture boundaries.

Architecture tests solve a completely different problem:
*   **Project-Wide Scope**: Archest builds a full project dependency graph. It easily detects circular imports between deep slices or ensures that a `Service` layer never accesses a `Controller`.
*   **Custom Extensibility**: You can write highly specific, custom architectural constraints for your exact business domain directly in your testing language, right next to your unit tests.

> Use linters for micro-level code quality. Use Archest for macro-level codebase boundaries.

## Safeguarding AI-Generated Code

As AI coding agents become more active in codebases, they generate code at an unprecedented speed. While AI is excellent at solving localized logic tasks (e.g. writing a specific function or class), it often lacks the macro-level context of a project's intended architecture.

Without guardrails, an AI agent might:
*   Accidentally import a UI component into a database service.
*   Create a circular dependency between two domain modules to quickly share a type.
*   Violate Layered Architecture boundaries (e.g. importing `Controllers` into `Repositories`).

**Archest acts as an automated, unbreakable guardrail.** Any code generated by an AI agent (or a human developer) that violates your domain boundaries will immediately fail the test suite. This forces the agent to respect your architecture, guaranteeing that your codebase remains perfectly decoupled no matter how fast it grows.

To further enhance the experience for AI agents, we provide an [Official Agent Skill](./agent-skills.md) that gives the agent the explicit context and API documentation needed to write flawless architecture tests.

## Key Features

*   ⚡️ **Native Performance**: Parses files directly using a blazing-fast native Rust core (`archest-core`) powered by `tree-sitter`.
*   🧪 **Seamless Integrations**: Custom `expect` matchers for Vitest/Jest, a JUnit 6 Jupiter Extension, and native Kotlin DSL matchers for Kotest.
*   🔄 **Cycle Detection**: Automatically catch circular dependencies between modules or files before they tangle your codebase.
*   🏗️ **Layered Architecture**: Declare strict boundary rules for architectural layers (e.g., Domain, Application, Infrastructure).
*   📐 **Structural Metrics**: Compute and enforce bounds for Cyclomatic Complexity, Maintainability Index, and Distance from the Main Sequence.
